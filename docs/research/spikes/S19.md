# S19: which local embedding model for semantic search?

Run: 2026-09-27, offline apart from downloading the models, on an Apple-silicon Mac (release builds). No Graph calls and no user data: the labelled set is invented ([S19-corpus.tsv](S19-corpus.tsv)).

Asked for rung 9c (D-042 deferred semantic search; BK chose a local model in the daemon, so task text never leaves the Mac). Which runtime and model finds "Book teeth cleaning" for `dentist`, builds on all three release targets with no library the user must install, and costs the least?

## Answer

**Model2Vec's `potion-base-8M`, run by `model2vec-rs` 0.3 (pure Rust).** It answered 25 of 32 queries with the expected task first and 31 of 32 in the top five, as well as a BERT model (`bge-small-en-v1.5`) did, at a quarter of the download, 250 times the speed, and without ONNX Runtime, which can't be built for the Intel Mac release target. Confidence: high on the choice, medium on the quality numbers (a small set written by us).

## Method

- **Labelled set:** 50 invented tasks (a few with notes) and 32 queries, each naming the task(s) that should come back ([S19-corpus.tsv](S19-corpus.tsv)). 29 queries share no word with the task (`dentist` → "Book teeth cleaning", `pet` → "Take the dog to the vet", `retirement` → "Sort out the pension paperwork"); 1 is a paraphrase sharing a word (`vehicle insurance`), 2 are plain keyword queries (`pharmacy`, `car`), to check semantic ranking doesn't lose what keyword search finds.
- **Text embedded:** the title, then the notes on the next line, as the FTS index holds them (D-041). **Ranking:** cosine similarity over every task, best first.
- **Scores:** hit@1, hit@3 and hit@5 (an expected task at or above that rank) and mean reciprocal rank. **Keyword baseline:** every query word as a prefix of a word in the task, as `search` finds them.
- **Speed:** embedding 2,000 short tasks (the set repeated with a number appended) in batches of 64, after loading.
- **Harnesses:** throwaway Rust binaries, one per runtime, not kept.

## Results

| Model (runtime) | Download | Dim | Load | 2,000 tasks | hit@1 | hit@3 | hit@5 | MRR |
|---|---|---|---|---|---|---|---|---|
| Keyword search (FTS-like) | – | – | – | – | 2/32 found at all | | | |
| potion-base-4M (model2vec-rs) | 15.8 MB | 128 | 20 ms | 17 ms | 23 | 28 | 29 | 0.804 |
| **potion-base-8M (model2vec-rs)** | **30.9 MB** | **256** | **20 ms** | **16 ms** | **25** | **28** | **31** | **0.846** |
| potion-base-32M (model2vec-rs) | 130.7 MB | 512 | 59 ms | 17 ms | 25 | 28 | 30 | 0.848 |
| potion-retrieval-32M (model2vec-rs) | 130.7 MB | 512 | 53 ms | 16 ms | 24 | 28 | 29 | 0.823 |
| bge-small-en-v1.5 (fastembed 7.1, ONNX) | 129 MB | 384 | 3.3 s | 3.98 s | 25 | 31 | 31 | 0.865 |

- **What every model missed:** `holiday` → "Book flights to Lisbon" (rank 26 for potion-base-8M, 41 for bge-small). The 8M model also ranked `groceries` → "Buy milk and eggs" 4th (behind "Plan meals for the week", which isn't wrong), `reimbursement` → the expense report 4th and `programming` → "Read chapter 4 of the Rust book" 5th.
- **The keyword queries** (`pharmacy`, `car`) came first by meaning alone, so merging in FTS (hybrid ranking) had nothing to fix in this set, and isn't built.
- **Query cost:** embedding a query and scoring 2,000 256-float vectors by brute force took under a millisecond (0.7 ms including computing norms, which the build avoids by storing unit vectors). No vector index (sqlite-vec) is needed at To Do's scale.
- **A score floor:** with potion-base-8M, the expected tasks scored 0.25–0.71 where the model found them easily, but two it ranked in its top five scored low: the expense report for `reimbursement` (0.18) and the Rust book for `programming` (0.14). Across the 32 queries, the unrelated tasks scored from −0.20 to 0.51, and 88% of them (1,371 of 1,556) under 0.15. The build drops results under 0.15: a search returns a shorter list instead of every task in order, a query of unknown words (`zebra`) returns nothing, and of this set only `programming` loses its task (30 of 32 in the top five instead of 31).

## Builds on the release targets

The release workflow builds natively on `ubuntu-24.04` (x86_64 Linux), `macos-15` (aarch64) and `macos-15-intel` (x86_64 macOS), with no system libraries installed.

- **model2vec-rs:** pure Rust with `default-features = false` and the tokenizer's `fancy-regex` engine (its default, `onig`, compiles C). `cargo tree` has no `cc` at all. Built and ran on aarch64-apple-darwin; built for x86_64-apple-darwin and ran under Rosetta with the same scores; built and linked for x86_64-unknown-linux-gnu (with `cargo zigbuild`, not run). The whole harness binary was 5.0 MB.
- **fastembed / ort:** `ort-sys` 2.0.0-rc.13 downloads a prebuilt ONNX Runtime at build time, and has none for x86_64-apple-darwin: `cargo build --target x86_64-apple-darwin` fails with "no prebuilt binaries available for target x86_64-apple-darwin". The Intel Mac job would need ONNX Runtime built from source, or the user to install it and load it dynamically. The aarch64 harness binary was 33.5 MB.
- **candle with a small BERT:** not tried. It would be in bge-small's class for download and speed (the same kind of model), with more code of our own for the tokenizer and pooling, and the set gives no quality it could add over potion-base-8M.

## What the choice costs ms-todo

- **Binary:** the aarch64 release binary grew from 26,898,720 to 29,716,208 bytes (+2.8 MB, +10%), for the tokenizer and safetensors code. The model isn't in it.
- **First use:** a 30.9 MB download from Hugging Face (three files at revision `bf8b056651a2c21b8d2565580b8569da283cab23`, each checked against a pinned SHA-256), into the instance's data directory.
- **Memory:** about 30 MB in the daemon while semantic search is on (the embedding table as f32), none while it's off.
- **Storage:** 1 KB per task (256 f32s), so about 2 MB for 2,000 tasks.
- **English only:** the potion-base models are English. `potion-multilingual-128M` exists if that becomes a need (about 4 times the download).

## What it changes

- Rung 9c builds on potion-base-8M through `model2vec-rs`, downloads on first use, and ranks by brute-force cosine over vectors kept in SQLite (D-062).
- Hybrid ranking and sqlite-vec are left out, as above.

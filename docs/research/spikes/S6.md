# S6: do PATCH and DELETE honour If-Match with @odata.etag?

Run: 2026-09-24 14:15:29–14:16:23 UTC. Throwaway list `{L}`, tasks "S6 etag task A/B/C/D". Auth header redacted.

## Answer (it depends on the verb and the entity)

| Operation | If-Match = current etag | If-Match = stale etag | If-Match = garbage (`W/"garbage"`) | If-Match = `*` |
|---|---|---|---|---|
| `PATCH task` | 200 | **412** `ErrorIrresolvableConflict` | **500** `generalException` / `ErrorInternalServerError` | **500** |
| `DELETE task` | 204 | **204, deleted anyway** (tried twice, tasks B and C) | **204, deleted anyway** (task D) | not tried |
| `PATCH checklistItem` (using the *parent task's* etag) | 200 | **412** | **500** | |
| `DELETE checklistItem` (parent's stale etag) | | **412** | | |
| `PATCH list` | 200 | **200, applied anyway** | | |

Confidence: high (each cell observed directly; task DELETE ignoring If-Match reproduced three times).

Etag behaviour:
- Stable across reads: two GETs in a row returned the same `W/"<prefix>EHE00g=="`.
- The `ETag` response header equals `@odata.etag`.
- The strong form (etag without `W/`) is accepted on PATCH (200).
- **Any child change (checklist item, linked resource, attachment, extension) changes the parent task's etag** (S1, S2).
- A task change does **not** change its list's etag (`…EHE1BQ==` before and after a task PATCH).
- Checklist items have no etag of their own; they're guarded by the parent task's etag.
- Etags look like a mailbox-wide change counter (a shared account-specific prefix, written `<prefix>` here, and an incrementing suffix), so they are opaque and only equality is meaningful.

## Conclusion

- Use `If-Match` on **task PATCH** and **checklist-item PATCH/DELETE** (with the parent task's etag): 412 is reliable there.
- **Task DELETE and list PATCH ignore If-Match.** To avoid deleting a task someone just edited, do a conditional no-op first
  (e.g. GET and compare etag, then DELETE) and accept the small race, or accept last-write-wins for deletes.
- Never send an etag we didn't get from Graph: a malformed If-Match yields **500**, which the generic 5xx retry would retry
  pointlessly. Map 500 + `ErrorInternalServerError` on a request that carried If-Match to a non-retryable error, or just never send
  anything but a stored etag.
- 404 on DELETE = already gone = success.
- Because any child change moves the parent etag, a task-level If-Match also catches concurrent checklist edits (more 412s than
  field-level conflicts justify); the 04 policy of "re-fetch, compare fields, re-send" handles this.

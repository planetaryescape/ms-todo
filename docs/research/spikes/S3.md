# S3: is $select rejected on To Do endpoints for a personal account?

Run: 2026-09-24 14:11:46 and 14:15:02–14:15:14 UTC. Throwaway list `{L}` (see S1). Auth header redacted.

## Answer

**Yes. `$select` naming almost any real property is a 400 `invalidRequest` / innerError `RequestBroker--ParseUri`, on every To Do
surface we tried (task list, single task, tasks/delta, lists, single list, lists/delta), on v1.0 and on beta.**
The few `$select` values that don't fail (`id`, `lastModifiedDateTime`, `*`) are silently ignored: the full object comes back.
Confidence: high. MAG&Cie's report is confirmed.

## Conclusion

Never send `$select` to To Do endpoints. Payloads are small anyway (a task is ~11–15 keys). Delta accepts no `$select`, `$filter` or
`$top`; page size is controlled with `Prefer: odata.maxpagesize` only (see P1). Confidence: high.
